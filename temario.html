Parte 1 · Lo estático y Jekyll

Por qué un generador de sitios estáticos y cómo está armado un sitio de Jekyll.

01. Por qué un generador de sitios estáticos

Del HTML escrito a mano a las plantillas: qué problema resuelven Jekyll y sus parecidos.

  • El problema: el mismo menú copiado en cincuenta archivos
  • Sitio estático, sitio dinámico y lo que hay en medio
  • Historia: Jekyll (2008) y el blog como texto en un repositorio
  • Jekyll, Hugo, Eleventy y Astro: en qué se parecen y cuándo elegir cada uno
  • Cuándo un sitio estático no alcanza (las aplicaciones están en Aplicaciones web)

Laboratorios

  • Cambia el menú de un sitio de diez páginas: a mano, archivo por archivo, y con una plantilla. Cuenta los archivos que tocas

Lo que te llevas: Escribir cada cosa una sola vez y dejar que el generador la repita.

02. Instalar Jekyll y el primer sitio

Ruby, Bundler y Jekyll en cada sistema operativo, jekyll new y el servidor local que recarga solo.

  • Ruby y Bundler: lo justo para usarlos, con los comandos de cada sistema operativo
  • jekyll new y lo que crea
  • bundle exec jekyll serve: el sitio en tu computador y la recarga en vivo
  • El Gemfile y la gema github-pages: la misma versión que usa GitHub
  • El camino sin instalar nada: editar en GitHub y dejar que Pages construya
  • Errores comunes al instalar y cómo leerlos

Laboratorios

  • La terminal simulada: corre cada comando y mira qué carpetas y archivos aparecen

Lo que te llevas: Probar en local con las mismas versiones que en producción.

03. La estructura de un sitio Jekyll

Qué es cada carpeta con guion bajo, qué es el front matter y cómo se convierte todo en la carpeta _site.

  • _config.yml: la configuración y las variables del sitio
  • _layouts, _includes, _data, _posts y _sass
  • El front matter: la ficha YAML de cada página
  • Lo que se procesa y lo que se copia tal cual
  • _site: el resultado, que nunca se edita a mano
  • El orden de la construcción: leer, renderizar Liquid, convertir Markdown y escribir

Laboratorios

  • El recorrido de un archivo: elige uno del proyecto y mira por qué etapas pasa hasta llegar a _site
  • Explorador de un sitio real: abre cada carpeta de este mismo sitio y mira qué página genera

Lo que te llevas: Fuente y resultado separados: se edita la fuente y se regenera.

Parte 2 · Plantillas, contenido y datos

Liquid, layouts, includes, Markdown, datos y colecciones: las piezas que evitan repetir.

04. Liquid: objetos, etiquetas y filtros

El lenguaje de plantillas de Jekyll: mostrar variables, decidir, repetir y transformar texto.

  • Objetos: {{ page.title }}, site y content
  • Etiquetas: if, for, assign y capture
  • Filtros: fechas, texto, listas y relative_url
  • Espacios en blanco y el control con {%- y -%}
  • Lo que Liquid no puede hacer, a propósito

Laboratorios

  • Patio de Liquid: escribe una plantilla y unos datos y mira el HTML que sale, con los errores marcados
  • Encadena filtros sobre una lista de proyectos: ordena, filtra y agrupa, y mira cada resultado intermedio

Lo que te llevas: La plantilla decide cómo se ve; los datos, qué se muestra.

05. Layouts e includes: no repetir HTML

Una plantilla de página que envuelve a otras y piezas pequeñas que se reúsan con parámetros.

  • El layout base: head, encabezado, {{ content }} y pie
  • Layouts que heredan de otro: página, artículo y proyecto
  • Includes: el menú, la tarjeta y el pie como piezas sueltas
  • Includes con parámetros: una tarjeta para cualquier proyecto
  • Cuándo un include y cuándo un layout

Laboratorios

  • Muñecas rusas: cambia el layout de una página y mira cómo se envuelven las capas
  • La tarjeta con parámetros: pasa otros datos al include y mira la tarjeta cambiar

Lo que te llevas: Componentes pequeños con parámetros, ensamblados por layouts.

06. Contenido: páginas, artículos y Markdown

Escribir en Markdown, organizar artículos por fecha y armar direcciones limpias.

  • Markdown con kramdown: lo básico y sus extensiones
  • Páginas y artículos (_posts): el nombre del archivo con fecha
  • Enlaces permanentes (permalink) y direcciones limpias
  • Borradores, categorías y etiquetas
  • Extractos, paginación y lista de artículos
  • Imágenes y archivos dentro del contenido

Laboratorios

  • Cambia el permalink de un artículo y mira la dirección final y qué enlaces se rompen
  • Editor de Markdown con la vista de kramdown al lado

Lo que te llevas: El contenido en Markdown, sin HTML de presentación adentro.

07. Datos y colecciones

Archivos YAML como base de datos del sitio y colecciones para lo que no es un artículo.

  • _data: YAML, JSON y CSV como fuente única
  • Generar una sección completa desde un archivo de datos: el catálogo de proyectos
  • Colecciones: proyectos, cursos o recetas con su propia carpeta
  • defaults en _config.yml: el front matter que no hay que repetir
  • Datos que vienen de otro repositorio o de un script
  • El caso de este sitio: el índice de cursos sale de un solo archivo

Laboratorios

  • Edita el archivo de datos y mira cómo el catálogo se redibuja: agrega, cambia el estado y ordena
  • Datos o colección: clasifica diez contenidos y mira la estructura de carpetas que resulta

Lo que te llevas: Una fuente de datos única; las páginas se generan de ella.

08. Estilos, recursos y temas

Sass en Jekyll, los recursos estáticos y los temas: usarlos, sobrescribirlos o no usarlos.

  • Sass: variables y archivos parciales en _sass (CSS a fondo está en Páginas web)
  • La carpeta de recursos: CSS, imágenes y JavaScript
  • Temas como gema y remote_theme
  • Sobrescribir un archivo del tema sin copiarlo todo
  • Sin tema: un CSS propio con variables y modo oscuro

Laboratorios

  • Cambia el tema del sitio y mira qué se conserva y qué cambia
  • Sobrescribe un include del tema y mira cuál gana

Lo que te llevas: Los estilos en un solo lugar, con variables, y el tema como punto de partida, no como jaula.

Parte 3 · Publicar en GitHub Pages

Del repositorio a una dirección pública, con dominio propio, buscadores, analítica y revisiones automáticas.

09. Publicar en GitHub Pages

Sitio de usuario y de proyecto, la construcción clásica y la de GitHub Actions, y baseurl.

  • Sitio de usuario (usuario.github.io) y sitio de proyecto (/proyecto/)
  • La construcción clásica: rama, carpeta y los complementos permitidos
  • Construir con GitHub Actions: cualquier versión y cualquier complemento
  • baseurl y relative_url: el error de las rutas que más se repite
  • .nojekyll: publicar HTML ya generado sin que Jekyll lo toque
  • Lo mínimo de Git para publicar (Git a fondo está en DevOps)

Laboratorios

  • El viaje de un cambio: haz un commit y sigue la construcción hasta la página en línea
  • Rutas rotas: cambia baseurl y mira qué enlaces e imágenes se pierden

Lo que te llevas: Cada push publica: el repositorio es el sitio.

10. Dominio propio, buscadores y analítica

Un dominio con HTTPS, que los buscadores entiendan el sitio y saber quién lo visita.

  • Dominio propio: el archivo CNAME, los registros DNS y HTTPS
  • jekyll-seo-tag: las etiquetas para buscadores y redes en todas las páginas (qué es cada una y por qué está en Páginas web)
  • Mapa del sitio (jekyll-sitemap), fuente RSS (jekyll-feed) y datos estructurados desde el front matter
  • Analítica con un gestor de etiquetas: un include en el layout base y ninguna página sin él
  • Privacidad y aviso de cookies

Laboratorios

  • Vista previa al compartir: cambia el front matter y mira cómo se ve el enlace en un chat
  • Busca la página que no tiene analítica: el layout base contra una página suelta

Lo que te llevas: Lo que toda página debe llevar va en el layout base, no en cada página.

11. Mantener el sitio: revisiones automáticas

Una acción de GitHub que revisa enlaces, HTML y accesibilidad antes de publicar, y dependencias al día.

  • Qué se rompe en un sitio que crece: enlaces, imágenes, rutas y estilos
  • Revisar el resultado con html-proofer
  • Accesibilidad y rendimiento con Lighthouse en la integración continua
  • Actualizar Jekyll y las gemas sin sorpresas
  • Un sitio que falla al construir: leer el registro de la acción

Laboratorios

  • La revisión automática: rompe un enlace, haz push y mira la acción en rojo con el error exacto

Lo que te llevas: Que una máquina revise lo que se rompe siempre igual.

Parte 4 · Generar con IA, sin perder el orden

Qué hace mantenible un sitio y qué pedirle a un asistente de IA para que lo amplíe sin desordenarlo.

12. Qué hace mantenible un sitio Jekyll

Las reglas que permiten agregar la página cincuenta sin tocar las otras cuarenta y nueve.

  • Una fuente para cada cosa: datos, estilos, menú y analítica
  • Includes pequeños con parámetros, layouts pocos
  • Convenciones de nombres de archivos y carpetas
  • Nada de HTML de presentación dentro del contenido
  • Señales de un sitio que se desordena: duplicados, estilos en línea y rutas fijas

Laboratorios

  • Detector de olores: carga un sitio de ejemplo y marca los duplicados, los estilos en línea y las rutas fijas

Lo que te llevas: Agregar contenido no debería obligar a tocar plantillas.

13. El archivo de instrucciones del sitio

Un archivo en el repositorio que le dice a cualquier asistente de IA cómo está hecho el sitio y qué reglas no se rompen.

  • Por qué un asistente desordena un sitio: no sabe dónde va cada cosa
  • Qué va en el archivo: estructura, convenciones, comandos y reglas
  • CLAUDE.md, AGENTS.md y sus parecidos: el mismo propósito
  • Reglas que se verifican: lo que el asistente debe correr antes de terminar
  • Una plantilla de instrucciones para un sitio Jekyll

Laboratorios

  • El mismo pedido con y sin el archivo de instrucciones: compara la estructura de archivos que resulta

Lo que te llevas: Las reglas del sitio escritas en el repositorio, no en la memoria de alguien.

14. Prompts para crear: el sitio, una página, una sección

Pedidos listos para usar, con su estructura: contexto, qué crear, dónde va y cómo se verifica.

  • La anatomía de un buen pedido: contexto, resultado, restricciones y verificación
  • Prompt para el esqueleto de un sitio nuevo con una estructura mantenible
  • Prompt para una página nueva que usa el layout y los includes existentes
  • Prompt para una sección generada desde un archivo de datos
  • Prompt para un componente (include) con parámetros
  • Prompt para una colección nueva con su layout

Laboratorios

  • Arma tu prompt: elige las piezas del pedido y mira cómo cambia lo que genera el asistente
  • Prompt vago contra prompt completo: el mismo pedido y los dos árboles de archivos lado a lado

Lo que te llevas: Pedir el resultado, dónde va y cómo se comprueba, no solo «hazme una página».

15. Prompts para cambiar y revisar

Pedidos para ordenar lo existente, auditarlo y revisar lo que generó el asistente antes de publicar.

  • Prompt para encontrar y quitar duplicados
  • Prompt para pasar contenido repetido a un archivo de datos
  • Prompt para cambiar el diseño sin tocar el contenido
  • Prompt para auditar enlaces, accesibilidad y analítica
  • Revisar lo que hizo el asistente: el diff, la construcción local y las revisiones automáticas
  • Una biblioteca de prompts del sitio, versionada en el repositorio

Laboratorios

  • Revisa el diff de un cambio generado: marca lo que aceptas y lo que pides corregir

Lo que te llevas: El asistente propone; el diff, la construcción y las revisiones deciden.

16. Proyecto final: tu sitio de punta a punta

El portafolio con blog y catálogo, publicado con dominio, revisiones automáticas, instrucciones y biblioteca de prompts.

  • La lista de lo que debe tener el sitio
  • Construirlo con el asistente, pedido por pedido
  • Publicarlo, verificarlo y medirlo
  • Agregar la página cincuenta: la prueba de que es mantenible

Laboratorios

  • Lista de verificación interactiva: marca cada punto y mira lo que falta para publicar

Lo que te llevas: Un sitio que crece sin que crezca el trabajo de mantenerlo.
